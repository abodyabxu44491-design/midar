# مدار | MIDAR — منصة إدارة المدارس

**برمجة وتطوير: المبرمج عبدالله السكني**

منصة لعدة مدارس. كل مدرسة معزولة عن غيرها داخل قاعدة البيانات نفسها، وكل دور له صفحة ودخول منفصلان.

| الصفحة | الرابط | من يدخلها |
|---|---|---|
| الرئيسية | `/` | صفحة فاضية: الشعار فقط، بلا أي روابط |
| لوحة المالك | رابط سري (`OWNER_PATH`) | أنت فقط، باسم مستخدم وكلمة مرور (ورمز تحقق ثنائي اختياري) |
| صفحة المدرسة | `/رمز-المدرسة` | الأهالي والطلاب برمز الصفحة (الأسماء فقط) |
| ملف الطالب | `/رمز-المدرسة/student` | بمعرّف الطالب فقط |
| باب منسوبي المدرسة | `/رمز-المدرسة/idara` | المدير والمعلمون والمحاسبون؛ النظام يفتح لكل حساب لوحته |

لكل مدرسة روابطها الخاصة باسمها، ولا يوجد رابط عام مشترك بين المدارس. عند إنشاء المدرسة من لوحتك تظهر **بطاقة تسليم** قابلة للطباعة فيها الروابط والرمز وبيانات دخول المدير.

## ما الذي تقدمه المنصة

| القسم | التفاصيل |
|---|---|
| لوحة المالك | المدارس، الاشتراكات والفواتير، طلبات التجربة، إعدادات المنصة، سجل العمليات |
| إدارة المدرسة | الطلاب، المعلمون، الفصول والمواد، السنة الدراسية، الحضور، الجدول، الاختبارات، كشوف الدرجات، الرسوم، طلبات التسجيل، التعاميم، التصدير، الإعدادات، السجل |
| بوابة المعلم | فصوله، جدوله وحصص اليوم، الحضور، الدرجات، الواجبات |
| بوابة المحاسب | المالية والرسوم فقط، بصلاحيات يحددها المدير |
| صفحة المدرسة | الصفوف وجداولها وأسماء الطلاب والبحث، وكلها اختيارية |
| ملف الطالب | البيانات، الجدول، الواجبات، الدرجات، الحضور، الرسوم والسداد |

### الجدول الدراسي
جدول لكل صف يُملأ بالاختيار من قائمة، وقاعدة البيانات نفسها تمنع وجود المعلم في فصلين بنفس الوقت. يظهر للمعلم (حصص اليوم وجدوله الأسبوعي)، ولولي الأمر داخل ملف الطالب، وفي صفحة الصف إذا فعّلته الإدارة.

### كشف الدرجات
كشف رسمي لكل طالب: الدرجات مجمّعة بالمادة، والنسبة والتقدير، والترتيب في الصف، وملخص الحضور، بشعار مدار وتوقيع المدير. يُطبع أو يُحفظ PDF من المتصفح، لطالب واحد أو لصف كامل دفعة واحدة. يُبنى من الاختبارات المعتمدة والمنشورة فقط.

### تنبيهات واتساب (بدون اشتراك)
المنصة تجهّز الرسالة وتفتح محادثة واتساب مع ولي الأمر من جوالك مباشرة: تنبيه غياب أو تأخر بعد تسجيل الحضور، وتذكير بالرسوم المتبقية من الفواتير، ورسالة عامة من قائمة الطلاب. القوالب قابلة للتعديل من الإعدادات، وتدعم المتغيرات: `{الطالب}` `{المدرسة}` `{الفصل}` `{التاريخ}` `{المبلغ}` `{الرابط}`. لا يُرسل الخادم أي رسالة ولا يوجد أي اشتراك في مزود رسائل.

### التحليلات والتنبيهات
- **الرئيسية:** بطاقات «يحتاج انتباهك» تجمع كل المعلّق: اختبارات تنتظر الاعتماد، تحويلات بانتظار التأكيد، طلبات تسجيل جديدة، فواتير تجاوزت موعدها، طلاب غابوا 3 أيام فأكثر، معلمون بدون إسناد، صفوف بدون جدول، طلاب بدون فصل.
- **تنبيهات مالية:** حركات تنتظر الاعتماد، حسابات رصيدها منخفض، ومسير رواتب الشهر إن لم يُنشأ.
- **قوائم عملية:** الغياب المتكرر والفواتير المتأخرة، مع زر واتساب بجانب كل اسم لتنبيه ولي الأمر مباشرة.
- **بحث سريع:** خانة واحدة تبحث في الطلاب والمعلمين والفواتير ومعرّفات الطلاب.
- **تبويب التحليلات:** نسبة الحضور شهريًا، الغياب شهريًا، الحضور حسب الصف، متوسط الدرجات حسب الصف والمادة، الأوائل، الطلاب تحت 60%، والتحصيل المالي شهريًا. كلها تُحسب آليًا، وتُصفّى حسب الفصل الدراسي والمدة.

### تسهيلات الإدخال
- **اسم ولي الأمر يُملأ تلقائيًا** من اسم الطالب (يوسف محمد علي ← محمد علي)، ويبقى قابلًا للتعديل.
- **أرقام أي دولة:** الرقم المكتوب بصيغة دولية (‎+967…‎ أو ‎00967…‎) يُحفظ موحدًا كما هو، والرقم المحلي (‎05…‎) يبقى كما هو ويُكمَّل برمز دولة المدرسة عند فتح واتساب. رمز الدولة يُختار من قائمة (السعودية، اليمن، الإمارات، مصر…) أو يُكتب يدويًا.
- **ربط الإخوة:** عند إدخال جوال مسجّل مسبقًا يظهر اسم ولي الأمر وأسماء إخوة الطالب في المدرسة.
- **الفصل يبقى مختارًا** للطالب التالي، ومفتاح Enter يضيف الطالب مباشرة.
- **تنظيف الأسماء:** المسافات الزائدة وعلامات التطويل تُزال تلقائيًا.
- الاستيراد من Excel يستفيد من كل ما سبق، فتكفي أعمدة ناقصة.

### حالة الطالب ونتيجة السنة
**حالة الطالب** واحدة من أربع، وتُغيَّر من تبويب الطلاب:

| الحالة | المعنى |
|---|---|
| على رأس القيد | طالب نشط يظهر في القوائم ويُفتح ملفه |
| متخرج | أنهى المرحلة |
| منقول لمدرسة أخرى | خرج بنقل |
| منسحب | انقطع أو سُحب ملفه |

الطالب خارج القيد يختفي من كل القوائم ولا يُفتح ملفه، وتبقى درجاته وفواتيره وسجل حضوره محفوظة، ويمكن إعادته للقيد بضغطة.

**نتيجة السنة** تُحسب آليًا: ناجح إذا بلغ معدله درجة النجاح المعتمدة للسنة (افتراضيًا 50%)، وراسب إذا قلّ عنها، و«غير مكتمل» إذا لم تُرصد له درجات منشورة. الحساب من الاختبارات المنشورة داخل فصول تلك السنة فقط.

### السنة الدراسية والفصول الدراسية
كل مدرسة لها سنة دراسية حالية وبداخلها فصلان أو ثلاثة، تُنشأ تلقائيًا عند إنشاء المدرسة.

- **الربط التلقائي:** أي اختبار أو فاتورة أو واجب جديد يُربط بالفصل الحالي بدون أي إدخال من المستخدم.
- **تبديل الفصل:** بضغطة واحدة من تبويب «السنة الدراسية». البيانات القديمة تبقى في فصلها ولا تتأثر.
- **كشف الدرجات لكل فصل:** تختار «الفصل الأول» أو «الثاني» أو «السنة كاملة»، والنسب والتقدير والحضور تُحسب لنطاق الاختيار.
- **بدء سنة جديدة:** نافذة واحدة من ثلاث خطوات:
  1. بيانات السنة الجديدة وعدد فصولها.
  2. ترفيع الصفوف: كل صف إلى أي صف (أو تخرّج طلابه).
  3. **مراجعة نتائج الطلاب:** يعرض لكل طالب معدله ونسبة حضوره ونتيجته (ناجح/راسب/غير مكتمل) والإجراء المقترح. الراسب يُعاد تلقائيًا ولا يُرفَّع، ويمكنك تعديل أي طالب إلى: ترفيع، إعادة، تخرّج، نقل لمدرسة أخرى، أو انسحاب.

  عند التنفيذ يُحفظ في سجل السنة المنتهية لكل طالب: صفه، ونتيجته، والإجراء، ومعدله، ونسبة حضوره. كل ذلك في عملية واحدة: إما تتم كاملة أو لا تتم، ولا تُحذف أي درجة أو فاتورة.
- **سجل الطالب:** سنواته السابقة وصفه ونتيجته ومعدله ونسبة حضوره في كل سنة.

### الواجبات
المعلم ينشئ الواجب لفصله ومادته، ويرصد من سلّم بضغطة على اسمه (شاشة مناسبة للجوال). ولي الأمر يرى في ملف ابنه الواجبات وموعد التسليم وحالته: «سُلّم» أو «لم يُسلّم».

### طلبات التسجيل (التحاق طالب جديد)
إذا فعّلتها المدرسة، يظهر في صفحتها زر «طلب تسجيل طالب جديد». يرسل ولي الأمر اسم الطالب والصف المطلوب وبياناته، فيصل الطلب لتبويب «طلبات التسجيل» في لوحة الإدارة، ومعه زر واتساب للتواصل. عند القبول يُنشأ ملف الطالب مباشرة بمعرّفه الخاص. الحد 3 طلبات لكل جهاز يوميًا لمنع الإزعاج.

### اشتراكات المدارس (لوحة المالك)
سعر سنوي ومدة سماح لكل مدرسة، وفواتير اشتراك تصدرها بزر واحد لكل التجديدات المستحقة خلال 30 يومًا. تسجيل السداد يمدد الاشتراك تلقائيًا ويعيد تفعيل المدرسة إن كانت موقوفة. المدارس التي تنتهي مدة سماحها تُوقف تلقائيًا كل ساعة، ويخرج مستخدموها فورًا. فواتير الاشتراك لا تراها المدارس إطلاقًا.

### الحضور السريع
وضع مخصص للجوال داخل الفصل: كل الطلاب حاضرون، والمعلم يضغط على أسماء الغائبين فقط (حاضر ← غائب ← متأخر ← بعذر)، ثم يحفظ الكل دفعة واحدة.

### نسخة من بيانات المدرسة
تصدير كل بيانات المدرسة من الإعدادات: ملفات Excel منفصلة (طلاب، حضور، درجات، جدول، فواتير، مدفوعات، الحسابات والحركات المالية، التبرعات، الرواتب، السنوات، الواجبات، طلبات التسجيل) أو نسخة JSON كاملة. يُقرأ على دفعات فلا يُقصّ، ويُسجَّل في سجل التدقيق.

### تثبيت كتطبيق (جوال وكمبيوتر)
تُثبَّت مدار كتطبيق على الجوال وعلى سطح المكتب بدون متجر، وباسم **مدار** وأيقونة الشعار.

| الجهاز | الطريقة |
|---|---|
| أندرويد | شريط التثبيت أسفل الصفحة ← «تثبيت» |
| آيفون وآيباد | شريط التثبيت ← «طريقة التثبيت» فتظهر الخطوات المصوّرة |
| ويندوز وماك | شريط التثبيت ← «تثبيت»، أو أيقونة التثبيت في شريط عنوان Chrome أو Edge |

شريط التثبيت مكان واحد ثابت في كل صفحات المنصة، ويختفي نهائيًا بمجرد تثبيت التطبيق: شعار مدار، وسطر تعريف، وزر تثبيت، وزر إخفاء. يظهر فقط عند إمكانية التثبيت، ويختفي نهائيًا بعد التثبيت، وإذا أخفاه المستخدم لا يعود قبل شهر. لا تُستخدم أي إيموجي أو رموز نصية في الواجهة، كل الأيقونات SVG.

عند التثبيت يظهر اسم المنصة وأيقونتها ولقطات من الشاشة في نافذة التثبيت. عامل الخدمة يخزّن الشعار والخطوط والتصميم فقط، **ولا يخزّن أي بيانات طلاب ولا أي استجابة من الخادم**، حتى على الأجهزة المشتركة.

### التصميم على الجوال والكمبيوتر
- **الجوال:** أزرار بمساحات لمس مريحة، وحقول بحجم يمنع تكبير الشاشة تلقائيًا في iOS، ومراعاة الحواف المنحنية والشريط السفلي.
- **الكمبيوتر:** التبويبات تتحول إلى قائمة جانبية ثابتة، والمحتوى يتوسع حتى 1280 بكسل، وملف الطالب يُعرض في عمودين.
- **التطبيق المثبّت:** شريط العنوان يندمج مع تصميم المنصة على سطح المكتب.

### الصفحة التسويقية وطلبات التجربة
من لوحة المالك تختار شكل الصفحة الرئيسية: فاضية (الشعار فقط) أو صفحة تسويقية تعرض المزايا والباقات ونموذج طلب تجربة. الطلبات تصل في تبويب «طلبات التجربة»، ومنها زر واتساب للتواصل، وزر واحد يحوّل الطلب إلى مدرسة مشتركة مع بطاقة التسليم.

## أقسام المنصة — تشغيل وإيقاف

من الإعدادات ← أقسام المنصة، تُشغّل كل مدرسة ما تحتاجه فقط:

| المجموعة | الأقسام |
|---|---|
| الأكاديمي | الحضور، الجدول الدراسي، الاختبارات، كشوف الدرجات، الواجبات |
| التواصل والتسجيل | التعاميم، رسائل واتساب، طلبات التسجيل، التحليلات |
| المالية | الرسوم والفواتير، النظام المالي، التبرعات، الرواتب، التحويل بين الحسابات |

- القسم الموقوف **يختفي من التبويبات** في لوحة الإدارة وبوابة المعلم وبوابة المحاسب، **ويرفضه الخادم بـ 404** فلا يُفتح برابط مباشر.
- البيانات المسجّلة لا تُحذف، وتعود كما هي عند إعادة التشغيل.
- قيود منطقية محفوظة في قاعدة البيانات: كشوف الدرجات تحتاج الاختبارات، والتبرعات والرواتب والتحويلات تحتاج النظام المالي.
- التبرعات والرواتب **موقوفة افتراضيًا** لأن أكثر المدارس الصغيرة لا تحتاجها.

## مصمم الاختبارات الورقية (الاختبارات والامتحانات)

قسم في بوابة المعلم («الاختبارات والامتحانات») ولوحة الإدارة («الاختبارات الورقية»)، ويُشغَّل أو يُوقف لكل مدرسة من «أقسام المنصة». منفصل عن «رصد الدرجات»، ويمكن إنشاء سجل درجات من أي اختبار معتمد بزر واحد.

**طرق الإنشاء:** جديد خطوة بخطوة، سريع (المادة والدرجة وعدد الأسئلة فقط)، من بنك الأسئلة (عدد كل نوع ومستوى الصعوبة والوحدة)، نسخ اختبار سابق (بنفس الأسئلة أو بأسئلة جديدة من البنك، مع إعادة توزيع الدرجات)، من قالب محفوظ، أو استيراد ملف مصدَّر من مدار.

**المصمم أربع خطوات:** معلومات الاختبار (تُعبأ من إسناد المعلم والفصل الحالي) ← الأسئلة (أقسام، سحب وإفلات بين الأسئلة والأقسام يعمل باللمس أيضًا، تكرار واستبدال من البنك) ← تصميم الورقة (4 قوالب، حجم الورق والاتجاه والهوامش والخطوط، وما يظهر في الورقة، ومعاينة حية) ← المعاينة والطباعة. كل تغيير يُحفظ تلقائيًا، والحفظ من نافذة قديمة يُرفض بدل أن يمسح عمل نافذة أخرى، ويظهر للمعلم تنبيه «لديك اختبار غير مكتمل».

**أنواع الأسئلة (12):** اختيار من متعدد، اختيار أكثر من إجابة، صح أو خطأ، أكمل الفراغ، قصير، مقالي، توصيل، ترتيب، بصورة، بجدول (مع دمج الخلايا)، رياضي، مخصص. المعادلات تُكتب بين علامتي `$ … $` وتُعرض بمحرك KaTeX المستضاف داخل المنصة. لكل سؤال: إجابته، والحل النموذجي، وملاحظات التصحيح (للمعلم فقط).

**الدرجات:** مجموع كل قسم والاختبار يُحسب فورًا وفي الخادم، وتنبيه عند اختلافه عن الدرجة النهائية، ولا يُعتمد اختبار ناقص.

**النماذج A–D:** نفس الأسئلة بترتيب مختلف للأسئلة و/أو الخيارات. الترتيب ثابت بالبذرة: النموذج B هو نفسه في كل طباعة، ونموذج إجابة مستقل لكل نموذج. عمود التوصيل وعناصر الترتيب تُخلط دائمًا حتى لا يُطبع الحل جاهزًا.

**الطباعة:** محرك صفحات يقيس الورق الحقيقي بالمليمتر، فالمعاينة هي نفسها الطباعة. لا ينقسم السؤال بين صفحتين، والعنوان لا يبقى وحيدًا، وأسطر الإجابة الطويلة تكمل في الصفحة التالية، و«صفحة 1 من 5» لكل نسخة. أوراق بأسماء طلاب الشعبة (مع توزيع النماذج بالتناوب)، وطباعة النماذج منفصلة، ونموذج الإجابة وحده أو مع الاختبار. الطباعة الرسمية بعد الاعتماد فقط، والمعاينة قبله بعلامة «مسودة».

**حفظ PDF:** عبر نافذة الطباعة في المتصفح («حفظ بتنسيق PDF») من نفس الصفحات المقسّمة وبخطوط مستضافة داخل المنصة، لذا يطابق المعاينة. لا يوجد توليد PDF في الخادم حاليًا (يحتاج Chromium في الخادم).

**بنك الأسئلة:** حسب المادة والصف والوحدة والدرس والنوع والصعوبة، مع البحث والإحصاءات. أسئلة المعلم له، ويمكنه مشاركتها مع معلمي المادة نفسها. السؤال يُنسخ إلى الاختبار، فتعديل البنك لاحقًا لا يغيّر اختبارًا قائمًا.

**سياسة المدرسة (الإدارة ← الاختبارات الورقية ← الإعدادات):** اشتراط اعتماد الإدارة قبل الطباعة، وإعادة فتح المعلم لاختباره المعتمد، وطباعة المعلم لنموذج الإجابة، وشعار المدرسة (يُرفع مرة واحدة)، والتعليمات الافتراضية. الاختبارات المنتظرة تظهر في مركز التنبيهات.

**الحماية:** المعلم لا يرى إلا اختباراته وأسئلته والمشترك في مواده، ولا ينشئ اختبارًا إلا لمادة وصف مسندَين له. نموذج الإجابة له مسار وصلاحية مستقلة، ولا يوجد أي مسار عام لأوراق الاختبارات. الاختبار المعتمد مقفل داخل قاعدة البيانات نفسها (مشغّل)، ولا يُحذف إلا المسودة. الصور تُفحص بمحتواها الفعلي لا بامتدادها، وصورة مدرسة أخرى تُحذف من المحتوى. اسم الطالب في الورقة المطبوعة بدون معرّفه السري.

## معالج الإعداد والهيكل الأكاديمي

**المعالج يملأ الشاشة قبل ظهور اللوحة** لأي مدرسة جديدة، ويمكن تخطيه بزر واحد والدخول مباشرة، والعودة إليه لاحقًا من «الهيكل الأكاديمي».

**مكتبة المواد الكاملة:** 48 مادة مقسّمة سبع مجموعات (العلوم الشرعية، اللغات، الرياضيات والعلوم، الاجتماعيات، التقنية والمهارات، الفنون والرياضة، مواد إضافية) تغطي ما يُدرَّس في اليمن والسعودية والخليج ومصر والأردن والمدارس الدولية. المقترح لمرحلتك مفعّل مسبقًا، وتفعّل أو توقف أي مادة، وتضيف مواد يدويًا في أي وقت.

**أنماط تسمية الصفوف:** عربي كامل (الأول الابتدائي…)، عربي مختصر (الأول… الثاني عشر)، اليمن (الأول الأساسي…)، ودولي (Grade 1…).

**المدرسة الجديدة لا تفتح على لوحة فارغة:** يظهر «معالج الإعداد» بثلاث خطوات:
1. **بيانات المدرسة:** الاسم، النوع (أهلية/حكومية/عالمية/تحفيظ)، الجنس، الدولة، المدينة، العنوان، البريد، الهاتف.
2. **القالب والشعب:** تختار قالبًا (ابتدائية، متوسطة، ثانوية، ابتدائي ومتوسط، متوسط وثانوي، شاملة، روضة وابتدائي، أو بدون قالب)، وعدد الشعب لكل صف، ونمط التسمية (أ ب ج / A B C / 1 2 3).
3. **المواد:** تظهر مواد المرحلة مقترحة بعلامات، تزيل ما لا يُدرّس عندكم.

ثم تُنشأ المراحل والصفوف والشعب والمواد **دفعة واحدة**. مثال: قالب ابتدائي مع 3 شعب ينشئ 6 صفوف و18 شعبة («الأول - أ» … «السادس - ج») ويربط المواد بصفوف المرحلة.

**شاشة «الهيكل الأكاديمي»** تجمع كل شيء في مكان واحد: المراحل ← الصفوف ← الشعب ← المواد، ومنها:
- إضافة مرحلة أو صف أو مادة، وتعديل الأسماء، والحذف.
- **ترتيب الصفوف** بالأسهم.
- **إنشاء الشعب تلقائيًا**: تكتب العدد وتختار نمط التسمية فتُنشأ كلها.
- تعديل اسم أي شعبة، وربط الشعب غير المرتبطة بصفّها.
- لكل مادة: الاسم، الرمز، عدد الحصص الأسبوعية، والصفوف التي تُدرّس فيها، وإيقافها دون حذف.

**قواعد الأمان:** لا يُحذف صف أو مرحلة فيها طلاب، وإعادة تطبيق القالب لا تكرر شيئًا (تكمل الناقص فقط)، وكل ما يولّده القالب قابل للتعديل والحذف بعدها.

## المعلمون: ملف كامل واقتراح المواد

ملف المعلم يشمل الاسم واسم المستخدم والرقم الوظيفي ورقم الهوية والجوال والبريد والتخصص والقسم. وعند كتابة التخصص **يقترح النظام المواد المناسبة** ويعرض زرين: «ربطه بها في كل الفصول» أو «تخطي» — اقتراح لا يفرض. ويمكن تعديل الملف والإسناد لاحقًا، وتصدير قائمة المعلمين إلى Excel.

## قوالب الرسوم والتقسيط

بدل إدخال رسوم كل طالب:
- **قالب رسوم** لكل صف: الاسم، المبلغ، عدد الدفعات (حتى 12)، أول استحقاق، والفاصل بين الدفعات.
- **خصومات ومنح وإعفاءات ورسوم إضافية** لكل طالب (نسبة أو مبلغ)، تُحتسب تلقائيًا عند التطبيق.
- **معاينة قبل التطبيق** تعرض لكل طالب إجماليه وقيمة كل دفعة ومن هو معفى.
- التطبيق ينشئ فواتير الدفعات دفعة واحدة («دفعة 1 من 4» …) بتواريخ استحقاق محسوبة، ويفعّل الرسوم للطالب.
- **إعادة التطبيق لا تكرر شيئًا**: الطالب الجديد في الصف يأخذ فواتيره، والباقي يُتخطى (قيد فريد في قاعدة البيانات).

## الإجراءات الجماعية على الطلاب

تحديد عدة طلاب (أو تحديد الكل المعروض) ثم إجراء واحد: **نقل لشعبة**، تفعيل/إيقاف الرسوم، تغيير الحالة، وتصدير المحدد إلى Excel. كل ذلك داخل معاملة واحدة ومسجّل في سجل التدقيق.

## الجدول الدراسي: توليد تلقائي بموافقتك

تبويب «الجدول» صار أربعة أقسام:
- **جدول الصفوف:** التعديل اليدوي لكل شعبة كما هو.
- **إعدادات الجدول:** أيام الدراسة، عدد الحصص اليومية، بداية الدوام، مدة الحصة، الفسحة ومدتها — ويحسب النظام وقت كل حصة (7:30 إلى 8:15…).
- **توليد تلقائي:** يوزّع حصص كل مادة حسب عدد حصصها الأسبوعية وإسناد المعلمين، على كل الشعب أو المختارة منها.
  - **مسودة لا تُحفظ**: تُعرض جداول الشعب كاملة مع تنبيهات واضحة (مادة بلا معلم، وقت غير كافٍ، تعذّر وضع حصة)، ولا تُكتب إلا بزر «اعتماد المسودة».
  - **بلا تعارض:** معلم واحد لا يُوضع في شعبتين بنفس الوقت، ولا شعبة بحصتين، ويأخذ في حسابه جداول الشعب الأخرى القائمة.
- **فحص التعارضات:** يكشف أي تعارض معلم أو قاعة في الجدول المعتمد (وقاعدة البيانات نفسها تمنع تعارض المعلم والقاعة).

## توزيع المعلمين

شاشة مصفوفة: الصف ← الشعب في الصفوف والمواد في الأعمدة، وكل خلية قائمة معلمين (★ لمن يدرّس المادة فعلًا). تعدّل ما تشاء ثم **حفظ التوزيع** دفعة واحدة، مع تصدير التوزيع كاملًا إلى Excel.

## النسخ والتكرار

- **نسخ مواد صف إلى صف** (مع خيار استبدال مواد الهدف).
- **نسخ قالب رسوم** باسم جديد وصف آخر.
- **نسخ جدول شعبة إلى شعبة**: يُنسخ الجدول، والمعلم المشغول في نفس الوقت تُترك حصته بلا معلم بدل إنشاء تعارض.

## ترتيب الطلاب وصفحة ولي الأمر

- **تبويب الطلاب** لم يعد قائمة واحدة طويلة: يبدأ بالمراحل ← الصفوف ← الشعب، وكل بطاقة تعرض عدد الطلاب، وعند اختيار الشعبة تظهر قائمتها مرتبة في أعمدة. والبحث يعمل على كل المدرسة في أي وقت، مع زر «عرض كل الطلاب».
- **ملف الطالب لولي الأمر** صار صفحة بعرض كامل: رأس فيه اسم الطالب وفصله وأربعة مؤشرات (متوسط الدرجات، الغياب، التأخر، حالة الرسوم)، وقائمة أقسام جانبية: نظرة عامة، الدرجات، الحضور والغياب، الواجبات، الجدول، الرسوم والسداد، المعلمون، التعاميم — كل قسم صفحة مستقلة بدل تكديسها في صفحة واحدة.

## مركز التنبيهات

الرئيسية تعرض كل ما يحتاج انتباه المدير في مكان واحد، مرتبًا بثلاثة مستويات:
- 🔴 **عاجل:** تعارض في جدول الحصص، فواتير تجاوزت موعدها، حسابات رصيدها منخفض، طلاب غابوا 3 أيام فأكثر.
- 🟠 **يحتاج إجراء:** اختبارات تنتظر الاعتماد، تحويلات بانتظار التأكيد، حركات مالية معلّقة، طلبات تسجيل، طلبات تغيير كلمة مرور، مسير رواتب الشهر، طلاب لم يُسجَّل حضورهم اليوم.
- 🟢 **معلومات:** طلاب بلا فصل، طلاب بلا جوال ولي أمر، معلمون بلا إسناد أو بلا جدول، شعب بلا جدول.

**الضغط على أي تنبيه ينقلك مباشرة إلى القسم المعني.**

## الحقول المخصصة

كل مدرسة تضيف ما تحتاجه من معلومات بلا تعديل في البرمجة: رقم الحافلة، الحالة الصحية، المدرسة السابقة، أو أي حقل آخر.
- **الأنواع:** نص، رقم، تاريخ، قائمة خيارات، نعم/لا.
- **الخيارات:** مطلوب أو اختياري، ويظهر في بطاقة الطالب داخل اللوحة، ويمكن إظهاره لولي الأمر في ملف ابنه.
- التحقق يتم على الخادم: الرقم رقم، والتاريخ تاريخ، وقيمة القائمة من ضمن خياراتها، والمطلوب لا يُترك فارغًا.
- حذف الحقل يحذف قيمه لدى كل الطلاب، وكل تعديل مسجّل في سجل التدقيق.

## إسناد المعلمين

شاشة الإسناد صارت قائمة صفوف مطوية: تضغط على الصف فتُفتح مواده وحده، تختار، ثم «حفظ الصف» فيُغلق ويظهر ملخص ما اخترته، وتنتقل للصف التالي.

## أوراق للطباعة

تبويب مستقل في لوحة الإدارة:
- **بطاقات معرّفات الطلاب:** بطاقة لكل طالب فيها اسم المدرسة والشعار، واسم الطالب وفصله، ورابط صفحة المدرسة، ورمزها، ومعرّف الطالب، وسطر إرشادي لولي الأمر. تُطبع لفصل واحد أو للمدرسة كلها، وتُقص وتُسلَّم.
- **سجل الحضور الشهري:** جدول الشهر كاملًا لكل صف (الطلاب × أيام الشهر) برموز واضحة (✓ حاضر، غ غائب، ت متأخر، ع بعذر)، ومجاميع كل طالب ونسبة حضوره، وسطر توقيع المعلم والمدير.

## سجل العمليات: تصفية وبحث

تصفية السجل حسب القسم (الطلاب، الحضور، الرسوم…)، ونوع العملية (إضافة/تعديل/حذف)، ومدة زمنية، مع بحث داخل القيم نفسها، وتصدير المعروض إلى Excel.

## استيراد البيانات من ملفات

من الإعدادات ← استيراد البيانات: خمسة أنواع جاهزة — **الطلاب، المعلمون، الفصول، المواد، الموظفون**.

1. تنزيل القالب: ملف CSV بعناوين عربية وأمثلة، يفتح في Excel مباشرة بترميز سليم.
2. تعبئته وحفظه بصيغة CSV.
3. رفعه: تظهر **معاينة** لأول 10 أسطر قبل أي تغيير.
4. الاستيراد: **كامل أو لا شيء** — أي خطأ في أي سطر يُبطل الملف كله ويُعرض رقم السطر وسببه.

أثناء الاستيراد تعمل كل تسهيلات الإدخال: استنتاج اسم ولي الأمر، وتوحيد صيغة الجوال، وربط الإخوة، وتنظيف الأسماء، وربط الطالب بفصله بالاسم. واستيراد المعلمين يُنشئ حساباتهم وكلمات مرور مؤقتة تظهر مرة واحدة قابلة للنسخ أو الطباعة، ويُطلب من كل معلم تغييرها عند أول دخول.

## الاشتراك والدعم

قسم في إعدادات المدرسة يعرض: اسم المدرسة، حالتها، الباقة، عدد الطلاب من الحد، تاريخ الانتهاء مع عدّاد الأيام المتبقية، قيمة الاشتراك، ومدة السماح. ومنه ثلاثة أزرار:
- **تجديد الاشتراك** (تختار المدة).
- **ترقية الباقة** (تختار عدد الطلاب المطلوب).
- **طلب دعم**.

الطلب يصل إلى تبويب **«طلبات التجديد»** في لوحة المالك مع كل تفاصيل المدرسة واشتراكها، ومعه زر واتساب للتواصل، وأزرار: تم التواصل، تم التنفيذ، رفض — ورد الإدارة يظهر للمدرسة في إعداداتها. ولا تستطيع المدرسة إرسال طلبين من النوع نفسه قبل الرد على الأول.

**بيانات التواصل** (رقم واتساب الدعم وسطر التعريف) يضبطها المالك من «إعدادات المنصة»، فتظهر للمدارس داخل القسم نفسه. ولا يظهر أي اسم أو شعار مطوّر أسفل الصفحات.

## الإعدادات والمالية: قائمة أقسام

الإعدادات تفتح على **قائمة بطاقات** فيها كل الأقسام العشرة مع سطر تعريف لكل قسم. الضغط على بطاقة يفتح صفحة القسم وحده، وفي أعلاها **زر رجوع** للقائمة. الأقسام: أقسام المنصة، استيراد البيانات، صفحة المدرسة العامة، طرق السداد، رسائل واتساب، المستخدمون والصلاحيات، العملة، الدخول والأمان، نسخة من بياناتك، الاشتراك والدعم.

وتبويب **المالية** يتبع النمط نفسه: قائمة بطاقات ثم صفحة لكل قسم مع زر رجوع.

**ثبات العرض:** المنصة لا تتكبر ولا تتصغر بالإصبع (مثل التطبيق)، ولا يوجد تمرير أفقي، وحجم الخط ثابت على iOS.

## صفحة المدرسة العامة — كل عنصر اختياري

تتحكم إدارة كل مدرسة بما يظهر لزوار صفحتها من: الإعدادات ← صفحة المدرسة العامة.

| الخيار | ماذا يفعل |
|---|---|
| طريقة الدخول | الصفحة مفتوحة لمن يعرف الرابط، أو تحتاج رمزًا من المدرسة |
| قائمة الصفوف | الزائر يرى الصفوف، ويضغط على الصف ليفتحه |
| أسماء الطلاب | إظهار الأسماء داخل الصف أو إخفاؤها |
| البحث بالاسم | يعمل حتى لو أُخفيت الصفوف والأسماء |
| جدول معلمي الصف | المادة والمعلم لكل صف |
| جدول حصص الصف | جدول الأسبوع داخل الصف |
| طلب التحاق طالب جديد | نموذج تسجيل يصل لتبويب «طلبات التسجيل» |
| عدد الطلاب في الصف | إظهار العدد بجانب اسم الصف |
| تعاميم المدرسة | عرضها في الصفحة العامة |
| حالة السداد بجانب الاسم | موقوف افتراضيًا (انظر التحذير أدناه) |
| الدرجات / الحضور / المعلمون / الجدول / الواجبات داخل ملف الطالب | إظهار أو إخفاء كل قسم |

النظام يمنع إيقاف الصفوف والأسماء والبحث معًا، حتى لا تصبح الصفحة بلا فائدة.

> **تحذير عن حالة السداد:** إظهارها بجانب الأسماء يكشف الوضع المالي لأسرة الطالب لكل من يفتح الصفحة، وقد يُحرج الطالب أمام زملائه ويخالف نظام حماية البيانات الشخصية. الخيار موجود لأن القرار قرار المدرسة، لكنه موقوف افتراضيًا، وولي الأمر يرى رسومه داخل ملف ابنه في كل الأحوال.

**ملف الطالب لا يُفتح أبدًا إلا بمعرّفه السري**، مهما كانت هذه الإعدادات.

## طريقة السداد

1. **الإدارة** تضيف الحساب البنكي للمدرسة من: الإعدادات ← طرق السداد (اسم البنك، اسم الحساب، الآيبان).
2. **ولي الأمر** يضغط «ادفع» في ملف الطالب، فيظهر له:
   - الحساب البنكي مع زر نسخ للآيبان، ونص يكتبه في ملاحظة التحويل.
   - بعد التحويل يضغط «حوّلت المبلغ» ويرسل إشعارًا يحتوي المبلغ والتاريخ واسم المحوِّل ورقم العملية.
   - أو يختار الدفع النقدي بالحضور للمدرسة، وتظهر له التعليمات التي كتبتها الإدارة.
3. **الإدارة** تراجع الإشعار من تبويب «الرسوم» بعد مقارنته بكشف البنك:
   - **تأكيد:** تُسجَّل دفعة من نوع «تحويل» ويصدر إيصال برقم متسلسل.
   - **رفض:** مع سبب يظهر لولي الأمر.
4. **الدفع النقدي:** تسجله الإدارة مباشرة من الفاتورة، ويصدر له إيصال أيضًا.

الإشعار وحده لا يغيّر حالة السداد. الطالب لا يُعتبر مسددًا إلا بعد تأكيد الإدارة.

## الرفع على الإنترنت — ثلاثة مسارات

| المسار | التكلفة | متى تختاره |
|---|---|---|
| **مجاني: Neon + Render** | صفر | للبداية وأول المدارس. الشرح الكامل في `docs/DEPLOY-FREE.md` |
| سيرفر خاص (VPS) | 5 إلى 10 دولارات شهريًا | أداء ثابت بدون نوم. الملفات في `deploy/` |
| Firebase + Cloud SQL | 15 إلى 30 دولارًا شهريًا | استضافة داخل السعودية وتوسع أكبر |

الكود واحد في المسارات الثلاثة، والانتقال بينها لا يحتاج إلا تغيير متغيرات البيئة.

> **ملاحظة عن Firebase:** خطة Spark المجانية لا تشغّل Cloud Functions ولا Cloud SQL، فمسار Firebase يتطلب خطة Blaze. Analytics يعمل مجانًا في كل المسارات.

## الرفع على Firebase (المشروع: `midar-714c1`)

### كيف تعمل المنصة على Firebase

```
المتصفح ──► Firebase Hosting (الشعار والخطوط عبر CDN + شهادة HTTPS مجانية)
               │  كل الطلبات الأخرى
               ▼
         Cloud Functions ‹app› (نفس خادم Express) ──► Cloud SQL (PostgreSQL) في الدمام
               │
         Secret Manager (كلمات المرور والروابط السرية)
```

قاعدة البيانات **PostgreSQL** وليست Firestore، عن قصد، للأسباب التالية:
- بيانات الطلاب والمبالغ تحتاج علاقات صارمة ومعاملات كاملة.
- المنصة تحتاج قواعد حماية داخل القاعدة نفسها: منع الدفع الزائد، ثبات المدفوعات، وعزل المدارس.
- Cloud SQL خدمة من Google تعمل ضمن نفس مشروع Firebase.

### المتطلبات
- **خطة Blaze في Firebase (الدفع حسب الاستخدام):** مطلوبة للدوال وCloud SQL. أصغر خادم Cloud SQL يكلّف تقريبًا 10 إلى 30 دولارًا شهريًا حسب الحجم، والدوال والاستضافة شبه مجانية في البداية. **ضع تنبيه ميزانية (Budget alert) من Google Cloud Billing.**
- على جهازك: Node.js 22، وGit، و`npm i -g firebase-tools`.

### الخطوة 1: تفعيل الخدمات
1. افتح console.firebase.google.com ← مشروع **midar-714c1**، ثم رقِّ الخطة إلى **Blaze**.
2. من console.cloud.google.com (نفس المشروع) فعّل الخدمات التالية:
   - Cloud SQL Admin API
   - Cloud Functions
   - Cloud Run
   - Cloud Build
   - Artifact Registry
   - Secret Manager
   - Cloud Scheduler

### الخطوة 2: إنشاء قاعدة البيانات
1. من Cloud SQL ← Create instance ← PostgreSQL 16:
   - Instance ID: `midar-db`
   - Region: `me-central2` (الدمام)
   - فعّل **Automated backups** و**Point-in-time recovery**، وهذا هو صمام الأمان الأهم.
   - فعّل **Deletion protection**.
2. افتح **Cloud Shell** (زر >_ أعلى الصفحة) ونفّذ:

```bash
git clone https://github.com/USERNAME/midar.git && cd midar
gcloud sql connect midar-db --user=postgres
```

داخل psql عرّف كلمتي المرور أولًا (غيّرهما لكلمتين قويتين)، ثم شغّل ملف الإعداد:

```sql
\set owner_pw '''كلمة-قوية-1'''
\set app_pw '''كلمة-قوية-2'''
\i db/setup-roles.sql
```

### الخطوة 3: الأسرار
من جهازك داخل مجلد المشروع، نفّذ:

```bash
firebase login
npm install
npm run owner:password     # يطبع OWNER_PASSWORD_HASH
npm run owner:totp         # يطبع OWNER_TOTP_SECRET — أضفه في تطبيق Google Authenticator
```

ثم احفظ الأسرار في Secret Manager:

```bash
firebase functions:secrets:set DATABASE_URL
#   القيمة: postgres://midar_app:كلمة-قوية-2@localhost/midar
firebase functions:secrets:set OWNER_PATH
#   القيمة: رابط سري طويل مثل /control-k29x7p4m8q
firebase functions:secrets:set OWNER_PASSWORD_HASH
firebase functions:secrets:set OWNER_TOTP_SECRET
```

أخيرًا امنح حساب خدمة الدوال صلاحية **Cloud SQL Client** من IAM. الحساب اسمه عادةً:
`266112517876-compute@developer.gserviceaccount.com`

### الخطوة 4: الترحيلات والنشر
شغّل Cloud SQL Auth Proxy في نافذة طرفية منفصلة:

```bash
cloud-sql-proxy --port 5432 midar-714c1:me-central2:midar-db
```

في نافذة أخرى أنشئ ملف `.env.local` يحتوي هذا السطر:

```
MIGRATION_DATABASE_URL=postgres://midar_owner:كلمة-قوية-1@127.0.0.1:5432/midar
```

ثم نفّذ:

```bash
npm run migrate
npm run deploy
```

بعد النشر تعمل المنصة على:
- `https://midar-714c1.web.app`
- لوحتك على `https://midar-714c1.web.app/control-...` (الرابط السري الذي اخترته)

> إذا ظهر أن المنطقة `me-central2` غير مدعومة للدوال أو الجدولة، غيّر `MIDAR_REGION` في `.env.midar-714c1` والمنطقة في `firebase.json` إلى `europe-west1`، واترك قاعدة البيانات في الدمام.

### الخطوة 5: الرفع على GitHub
1. أنشئ مستودعًا **خاصًا (Private)** باسم `midar` على github.com.
2. ارفع المشروع:

```bash
git remote add origin https://github.com/USERNAME/midar.git
git push -u origin main
```

3. للنشر التلقائي عند كل رفع، أضف من Settings ← Secrets ← Actions:
   - `GCP_SA_KEY`: مفتاح JSON لحساب خدمة له الصلاحيات التالية:
     - Firebase Admin
     - Cloud Functions Admin
     - Service Account User
     - Cloud SQL Client
     - Secret Manager Viewer
   - `MIGRATION_DATABASE_URL`: `postgres://midar_owner:كلمة-قوية-1@127.0.0.1:5432/midar`

   بعدها كل رفع إلى `main` يمر أولًا بالاختبارات، ثم الترحيلات، ثم النشر.

### الخطوة 6: ربط الدومين
1. اشترِ نطاقًا، مثل `midar.sa` من nic.sa أو `midar-edu.com` من أي مسجل.
2. من Firebase Console ← Hosting ← **Add custom domain** ← اكتب النطاق.
3. أضف السجلات التي يعرضها Firebase (TXT ثم A) في إعدادات DNS عند المسجل.
4. انتظر من ساعة إلى 24 ساعة. شهادة HTTPS تُصدر تلقائيًا.
5. حدّث `PUBLIC_URL` في `.env.midar-714c1` إلى النطاق الجديد، ثم نفّذ `npm run deploy`.
6. من Google Cloud ← APIs ← Credentials، قيّد مفتاح Firebase الموجود في `firebase-config.js` على نطاقك فقط.

## التشغيل على جهازك للتطوير

```bash
npm install
sudo -u postgres psql -v owner_pw="'dev-owner'" -v app_pw="'dev-app'" -f db/setup-roles.sql
```

أنشئ ملف `.env.local` بهذا المحتوى:

```
NODE_ENV=development
PORT=3000
DATABASE_URL=postgres://midar_app:dev-app@127.0.0.1:5432/midar
MIGRATION_DATABASE_URL=postgres://midar_owner:dev-owner@127.0.0.1:5432/midar
OWNER_PATH=/control-local-dev-path
OWNER_USERNAME=owner
OWNER_PASSWORD_HASH=...        # من npm run owner:password
COOKIE_SECURE=false
TRUST_PROXY=0
TEST_OWNER_PASSWORD=...        # كلمة المرور نفسها، للاختبارات
```

ثم نفّذ:

```bash
npm run migrate
npm run seed:demo     # مدرسة تجريبية
npm run dev
npm test              # الاختبارات
```
