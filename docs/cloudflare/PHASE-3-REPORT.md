# المرحلة الثالثة: تشغيل مدار على Cloudflare Workers

**التاريخ:** 5 نوفمبر 2026
**الحالة:** التشغيل المحلي على بيئة Workers الحقيقية مكتمل ومختبَر. **النشر على حساب Cloudflare (staging) ينتظر صلاحيات منك** (القسم 6).
**المراجع:** [المرحلة الأولى](PHASE-1-REPORT.md) · [المرحلة الثانية](PHASE-2-DESIGN.md)

## 1. الخلاصة

| | النتيجة |
|---|---|
| المنصة كاملة تعمل داخل بيئة Workers الحقيقية (`workerd`، عبر `wrangler dev`) | **نعم** |
| الاتصال بقاعدة البيانات عبر واجهة Hyperdrive نفسها المستخدمة في الإنتاج | **نعم**، والعزل بـ RLS يعمل كما هو |
| الصفحات والملفات ولوحة المالك وصفحة 404 مطابقة لخادم Node **بايتًا ببايت** | **نعم**، 16 مسارًا مقارنة |
| إرسال البريد من Workers عبر SMTP حقيقي | **يعمل** |
| الاختبارات على نسخة Workers | **408 من 431 نجحت**، وواحد تحقق منه منفصلًا، و**22** تعتمد على بدائل وهمية داخل عملية الاختبار نفسها فلا يمكن تشغيلها على خادم منفصل (القسم 4) |
| الاختبارات على Node بعد كل التعديلات | **انظر القسم 4.1** |
| أخطاء حقيقية اكتُشفت قبل أي نشر | **2**، أُصلحت (القسم 3) |
| Render وNeon والدومين | **لم يُمس أي شيء** |

## 2. ما الذي بُني

| الملف | الدور |
|---|---|
| `workers/api.js` | نقطة دخول Workers: تطبيق Express نفسه عبر `httpServerHandler` |
| `workers/setup.js` | يُحمَّل قبل التطبيق: يربط `waitUntil` وHyperdrive بطبقة `src/core/platform.js` |
| `workers/fs-shim.js` | نظام ملفات للقراءة فقط فوق ملفات الواجهة المضمّنة في الحزمة |
| `scripts/build-workers.js` | يرتب الملفات الثابتة على روابطها نفسها لتخدمها Cloudflare مباشرة (مجانًا، دون تشغيل الـ Worker)، ويحسب رقم الإصدار مرة واحدة عند البناء |
| `src/core/platform.js` | الفروق بين Node وWorkers في مكان واحد. **على Node لا يتغير أي سلوك** |
| `wrangler.jsonc` | إعداد Workers للتطوير المحلي وبيئة staging. لا يحتوي أي سر |
| `tests/smtp-sink.js` | خادم بريد محلي للاختبارات، يستقبل رسائل حقيقية من Workers |

**أوامر جديدة:** `npm run workers:build`، `npm run workers:dev`، `npm run workers:deploy:staging`.

**حجم الحزمة:** 9.6 ميغابايت غير مضغوطة (2 ميغابايت مضغوطة) (الحد 64 ميغابايت في الخطتين)، والملفات الثابتة 8 ميغابايت تخدمها Cloudflare منفصلة.

### التعديلات على الكود المشترك (كلها تبقي سلوك Node كما هو)

| التعديل | السبب |
|---|---|
| اتصال لكل معاملة على Workers (`pool.js`) | Workers لا تسمح باستخدام اتصال فُتح في طلب آخر. Hyperdrive يحتفظ بالمجمّع الحقيقي. `set_config('app.tenant_id')` وسياسات RLS لم تتغير |
| العمل بعد الرد يمر بـ `background()` | Workers تقطع أي عمل بعد الرد ما لم يُسجَّل بـ `waitUntil` |
| لا مؤقتات ولا قراءة Hyperdrive أثناء تحميل الوحدات | ممنوع في Workers (مخزن حد المعدل العام، منظف المهام) |
| عنوان الزائر من `CF-Connecting-IP` على Workers | لا يوجد عنوان اتصال في Workers. Cloudflare تضع هذا الرأس بنفسها ولا يمكن تزويره، بخلاف `X-Forwarded-For` |
| إيقاف ضغط Express على Workers | Cloudflare تضغط الردود بنفسها، فكان الضغط مزدوجًا |
| `qrcode-generator` باستيراد مباشر | `createRequire` لا يعمل داخل الحزمة |

## 3. أخطاء حقيقية اكتشفها التشغيل على Workers

1. **رسالة «تم الدخول إلى حسابك من جهاز جديد» وتنبيه «طلبات مرفوضة متكررة» كانا سيضيعان بصمت**، لأنهما يُرسلان بعد الرد دون تسجيل. اكتشفه اختبار البريد، وأُصلح بـ `background()`، وتحقق الاختبار نفسه من الوصول.
2. **عنوان الزائر كان مفقودًا**، وكان سيعطّل حدود المحاولات وقائمة العناوين المسموحة للمالك وسجل التدقيق. أُصلح.

بعد ذلك فحصت الكود آليًا بحثًا عن أي إرسال مشابه بعد الرد دون تسجيل، ولم يبق منه شيء في مسارات الطلبات.

## 4. نتائج الاختبارات

### 4.1 على Node (الخادم الحالي)
- **قبل التعديلات:** 431 اختبارًا. فشل 18 في ملف واحد بسبب تعديلي الملفات أثناء التشغيل، ونجح الملف نفسه 18/18 عند إعادته منفردًا.
- **بعد كل التعديلات:** _تُكتب النتيجة عند اكتمال التشغيل._

### 4.2 على Workers

| | العدد |
|---|---|
| إجمالي الاختبارات | 431 |
| نجح من التشغيل الأول الكامل | 406 |
| أُصلح بعده وتحقق منه | 2 (`gate-join-code`: صار الاختبار يرسل العنوان كما ترسله Cloudflare) |
| تحقق منه منفصلًا | 1 (إلزام تغيير كلمة المرور المؤقتة: الاختبار يغير متغيرًا داخل عمليته فلا يراه الخادم المنفصل، فشغّلت الخادم بالإعداد نفسه فنجح) |
| **تعتمد على بدائل وهمية داخل العملية** | **22** |

**الـ 22 لا تدل على خلل في Workers**، فهي تستبدل خدمة خارجية ببديل وهمي في ذاكرة عملية الاختبار، ثم تقرأ ما وصل إليه. الخادم المنفصل لا يرى ذلك البديل:

| الملف | البديل الوهمي | العدد |
|---|---|---|
| `accounts.test.js` | خوادم Google وApple (`setOAuthHttp`) | 4 |
| `ai.test.js` | مساعد الذكاء الاصطناعي (`setAiClient`) | 5 |
| `notification-engine.test.js` | مزود إشعارات الجوال (`setTransport`) | 5 |
| `notifications.test.js` | الإشعارات والرسائل النصية (`setTransport`) | 3 |
| `smart-gate.test.js`, `smart-gate-advanced.test.js` | الإشعارات (`setTransport`) | 3 |
| `owner-security.test.js`, `free-channels.test.js` | الإشعارات (`setTransport`) | 2 |

هذه الاختبارات تبقى تعمل على Node في كل تشغيل.

**ما لم يُتحقق منه بعد على Workers:** الإرسال الفعلي لإشعارات الجوال (مكتبة `web-push`)، وبوابة الرسائل النصية، وتسجيل الدخول عبر Google وApple، ومساعد الذكاء الاصطناعي. تحتاج اختبارًا بخوادم وهمية خارجية (كما فعلت مع البريد)، وهي **أول بند في المرحلة الرابعة**.

## 5. ما بقي للانتقال (المرحلة الرابعة)
- التحقق من إشعارات الجوال والرسائل النصية وGoogle وApple والذكاء الاصطناعي على Workers.
- نقل المهام المجدولة (التذكيرات، البوابة، الصيانة، مراقبة الاستهلاك، إعادة محاولات الإشعارات) إلى Cron وQueues. **على Workers لا تعمل حاليًا**، لأنها مؤقتات في `server.js` الخاص بـ Node.
- نقل الاستيراد الطويل إلى Queues (`waitUntil` يمنح 30 ثانية فقط بعد الرد).
- نقل حدود المعدل العامة إلى Cloudflare Rate Limiting (حاليًا تقريبية لكل نسخة).
- الملفات إلى R2، بعد تفعيله من حسابك.

## 6. ما أحتاجه منك للنشر على staging

1. **رمز Cloudflare API** بالصلاحيات: Workers Scripts (Edit)، Hyperdrive (Edit)، Account Settings (Read). يضاف في إعدادات بيئة هذه الجلسة (قائمة البيئة في شريط العنوان ← Edit) باسم `CLOUDFLARE_API_TOKEN`، ومعه `CLOUDFLARE_ACCOUNT_ID`. **لا ترسله في المحادثة.**
2. **قاعدة اختبار:** مشروع Neon مجاني منفصل ببيانات تجريبية فقط، ويضاف رابطه باسم `STAGING_DATABASE_URL`.

بعدها: إنشاء إعداد Hyperdrive، وضبط الأسرار التجريبية، والنشر على `midar-api-staging.<حسابك>.workers.dev`، وتشغيل الاختبارات نفسها عليه، وقياس زمن الاستجابة الفعلي.

## 7. طريقة إعادة التحقق محليًا
```
npm run workers:build
CLOUDFLARE_HYPERDRIVE_LOCAL_CONNECTION_STRING_HYPERDRIVE=<قاعدة محلية> npx wrangler dev
TEST_BASE_URL=http://127.0.0.1:8787 npm test
```
الإعدادات المحلية في `.dev.vars` (غير مرفوع إلى المستودع).
