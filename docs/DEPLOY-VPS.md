# التشغيل على سيرفر خاص + نطاق (المسار الموصى به)

سيرفر واحد صغير عليه كل شيء: المنصة وقاعدة البيانات. لا نوم، ولا حدود على عدد المدارس أو حجم البيانات (40 جيجابايت تكفي مئات المدارس).

| الجزء | الخدمة | التكلفة التقريبية |
|---|---|---|
| النطاق | Cloudflare Registrar | 10 إلى 11 دولار في السنة (`.com`) |
| السيرفر | Hetzner Cloud — أصغر سيرفر (2 معالج، 4 جيجا ذاكرة، 40 جيجا) | 4 إلى 6 يورو في الشهر |
| النسخ الاحتياطي التلقائي للسيرفر كاملًا | Hetzner Backups | +20% من سعر السيرفر (حوالي يورو واحد) |
| شهادة HTTPS | Let's Encrypt | مجانًا، وتتجدد وحدها |

**المجموع: حوالي 6 دولار في الشهر + 11 دولار في السنة للنطاق.** الأسعار من مواقع الشركات وقد تتغير قليلًا.

---

## 1) شراء النطاق (10 دقائق)

1. افتح `dash.cloudflare.com` وسجّل حسابًا مجانيًا.
2. من القائمة: **Domain Registration ← Register Domains**.
3. ابحث عن الاسم. اقتراحات: `midar.school`، `midarschool.com`، `midar-edu.com`، `getmidar.com`.
   - `.com` الأفضل للثقة وأرخص في التجديد.
   - تجنّب `.sa` الآن: يحتاج سجلًا تجاريًا سعوديًا.
4. ادفع بالبطاقة. Cloudflare تبيع بسعر التكلفة بدون زيادة في التجديد، والخصوصية (إخفاء بياناتك) مجانية.

## 2) إنشاء السيرفر (5 دقائق)

1. سجّل في `console.hetzner.cloud` (يطلب التحقق من الهوية أول مرة).
2. **New Project ← Add Server**:
   - **Location:** Nuremberg أو Falkenstein (ألمانيا، الأقرب للخليج واليمن عند Hetzner).
   - **Image:** Ubuntu 24.04.
   - **Type:** Shared vCPU ← أصغر خيار x86 بـ 4 جيجا ذاكرة (CX22 أو ما يقابله).
   - **Networking:** IPv4 + IPv6.
   - **SSH key:** إن لم تعرفه اتركه، وستصلك كلمة مرور root على البريد.
   - **Backups:** فعّله (نسخة يومية من السيرفر كاملًا لدى Hetzner، خارج السيرفر نفسه).
3. **Create & Buy now**، وانسخ **عنوان IP** للسيرفر.

## 3) ربط النطاق بالسيرفر (دقيقتان)

في Cloudflare: النطاق ← **DNS ← Records ← Add record**:

| Type | Name | Content | Proxy |
|---|---|---|---|
| A | `@` | عنوان IP للسيرفر | **DNS only** (السحابة رمادية) |
| A | `www` | عنوان IP للسيرفر | **DNS only** |

> اترك السحابة **رمادية**. البرتقالية تمرر الزوار عبر Cloudflare فيظهرون كلهم بعناوينها، وتتداخل حدود المحاولات بين المستخدمين.

## 4) التثبيت بأمر واحد (10 دقائق)

من جوالك (تطبيق Termius) أو من الكمبيوتر (Terminal أو PowerShell):

```bash
ssh root@عنوان-IP
```

ثم الصق الأمرين (غيّر النطاق والبريد):

```bash
curl -fsSL https://raw.githubusercontent.com/abodyabxu44491-design/midar/main/deploy/install.sh -o install.sh
sudo bash install.sh midar.example.com you@example.com
```

يطلب منك **كلمة مرور لوحة المالك** (12 حرفًا على الأقل)، ثم يجهّز كل شيء وحده:

- Node 22 وPostgreSQL على نفس السيرفر، والقاعدة لا تُفتح للإنترنت.
- مستخدمان للقاعدة بكلمات مرور عشوائية: مالك الجداول، ومستخدم التطبيق المقيد بعزل المدارس.
- ملف `.env` بكل الأسرار، ورابط سري للوحة المالك.
- المنصة كخدمة دائمة، تعود وحدها بعد أي توقف أو إعادة تشغيل للسيرفر.
- nginx، وشهادة HTTPS مع التحويل التلقائي من http.
- جدار حماية: لا يُفتح إلا SSH و80 و443.
- حماية من تخمين كلمات مرور SSH، وتحديثات أمنية تلقائية للنظام.
- نسخة احتياطية مشفرة يوميًا الساعة 3:17 فجرًا، تُحفظ 30 يومًا في `/var/backups/midar`.

في النهاية يطبع **رابط لوحة المالك**. احفظه مع ملف `/root/midar-credentials.txt`، وانسخ **مفتاح النسخ الاحتياطية** `/root/.midar-backup-key` إلى مكان آمن عندك.

## 5) نقل البيانات من Neon (إن كانت عندك مدارس حقيقية)

مرة واحدة، والسيرفر الجديد جاهز:

```bash
sudo /opt/midar/deploy/import-neon.sh 'رابط-المالك-من-Neon'
```

الرابط من Neon: **Connection Details**، بمستخدم `neondb_owner`. الأمر:

1. يأخذ نسخة من القاعدة المحلية أولًا.
2. ينزّل كل البيانات من Neon ويضعها في السيرفر.
3. يطبق الترحيلات ويعيد التشغيل.
4. يطبع عدد المدارس للتأكد.

> كلمات مرور المستخدمين والجلسات تنتقل كما هي، فلا يحتاج أحد تسجيل دخول جديد غير أن الرابط تغيّر.

## 6) بعد الانتقال

1. **الرابط الجديد:** تأكد أن `https://نطاقك` يفتح، وجرّب لوحة المالك ومدرسة.
2. **Render:** أوقف الخدمة القديمة (Settings ← Suspend)، ثم احذفها بعد أسبوع.
3. **Neon:** احتفظ بها شهرًا كنسخة إضافية، ثم احذف المشروع.
4. **GitHub ← Actions:** عطّل **Keep alive** (لم يعد مطلوبًا)، وعطّل **نسخة احتياطية** (قاعدة السيرفر لا تُفتح للإنترنت، والنسخ صارت على السيرفر وفي Hetzner Backups).
5. **روابط قديمة:** بطاقات أولياء الأمور المطبوعة بالرابط القديم تحتاج إعادة طباعة. بعد الانتقال تُطبع بالنطاق الجديد تلقائيًا (من `PUBLIC_URL`).

## التحديثات

بعد دمج أي تعديل في `main`:

```bash
sudo /opt/midar/deploy/update.sh
```

ينفّذ بالترتيب: نسخة احتياطية، ثم آخر كود، ثم الترحيلات، ثم إعادة التشغيل، ثم فحص أن المنصة تعمل. إن لم تعمل يطبع السجل، والنسخة الاحتياطية جاهزة.

## أوامر مفيدة

| الغرض | الأمر |
|---|---|
| حالة المنصة | `sudo systemctl status midar` |
| السجل المباشر | `sudo journalctl -u midar -f` |
| إعادة التشغيل | `sudo systemctl restart midar` |
| نسخة احتياطية الآن | `sudo /opt/midar/deploy/backup.sh` |
| حجم القاعدة | `sudo -u postgres psql -d midar -c "SELECT pg_size_pretty(pg_database_size('midar'))"` |
| المساحة المتبقية | `df -h /` |

**استرجاع نسخة احتياطية:**

```bash
gpg --batch --passphrase-file /root/.midar-backup-key -d /var/backups/midar/FILE.dump.gpg > /tmp/m.dump
sudo systemctl stop midar
sudo -u postgres pg_restore --clean --if-exists -d midar /tmp/m.dump
sudo systemctl start midar
```

## متى أكبّر السيرفر؟

من لوحة Hetzner: **Rescale** إلى سيرفر أكبر بضغطة، والبيانات تبقى كما هي (توقف دقيقة أو دقيقتين).

- السيرفر الصغير يتحمل عشرات المدارس.
- كبّره إذا ظل المعالج فوق 70% وقت الذروة (الصباح الباكر)، أو امتلأت المساحة فوق 70%. تراقب ذلك من تبويب **Graphs** في لوحة Hetzner.
